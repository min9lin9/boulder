# Boulder Quickstart

Status: ready

This is the first-run guided flow for a maintainer opening Boulder in a repository.

GJC and LazyCodex are adapter preferences. doctor verifies local installation before live execution; absent adapters stay configured-unverified and approval-gated.

## Checks

- manifest: pass - boulder.yaml
- operator-contract: pass - BOULDER.md
- repo-brief: pass - docs/REPO_BRIEF.md
- active-profile: pass - programming-default (built-in)
- executor-planning: pass - plan=gajae-code (detect-and-suggest; availability checked by doctor)
- executor-execution: pass - execute=lazycodex (detect-and-suggest; availability checked by doctor)

## Next Commands

- `boulder inspect --cwd . --json` - Read the repository shape before planning.
- `boulder profile list --cwd .` - See the available workflow profiles before routing work.
- `boulder profile resolve --cwd .` - Confirm the active plan/execute adapters and external-call policy.
- `boulder profile use programming-default --cwd .` - Select the default programming profile, or swap it for research-default or ops-default.
- `boulder pipeline --cwd . --friction medium` - Choose the default classification -> plan -> verify path.
- `boulder service-readiness --cwd . --json` - See whether repeatable service evidence is already present.
- `boulder export --cwd . --force` - Write shareable Codex workflow notes and handoff artifacts.
